# 家庭开销管理体系 · 总引导

管理一套已运行的家庭财务数据管线：**多源账单 → 腾讯文档总表（真相层）→ 本地 JSON（加工层）→ 单文件仪表盘（展示层）**。

## 体系架构

```
原始账单(PDF/eml/CSV/微信支付宝导出)
  ↓ [bill-source-parsing] 解析入卡明细表
腾讯文档《家庭资产配置总表》(file_id=YOUR_FILE_ID)
  ├─ 12+张卡明细表（真相层，只追加）
  ├─ 开销流水明细 SHEET_6TgC25（A-T 20列：基础+三分类+事件+复核+对冲）
  ├─ 信用卡月账单汇总验算 SHEET_D0xECl（checksum）
  └─ 分类法字典 SHEET_dcpMyb
  ↓ [multi-scheme-classify] 三分类引擎 → _v10_base.json
  ↓ [dedup-reconciliation] 去重+对账标注 → _v10_rows.json + _v10_recon.json
  ↓ [tencent-sheet-sync] 回写表格（下拉/验证/行号）
  ↓ [expense-dashboard] 生成开销分析仪表盘.html
```

## 月度更新流程（完整管线）

1. **收账单**（QQ邮箱 MCP + 用户本地导出）：搜当月 HSBC/招行/中信/太保账单邮件；微信/支付宝/银行流水从 App 导出（微信：我→服务→钱包→账单→账单下载→发邮箱，真xlsx可能在手机目录；支付宝：我的→账单→交易流水证明）
2. **解析入表**：新数据写对应卡明细表；整批重写明细表前先写"备用表 SHEET_hsgpLC"核对再替换正式
3. **分类复核**：multi-scheme 引擎重建 _v10_base.json → 用户在表格 R 列改（下拉选）→ apply_review.py 读回
4. **对账**：build_recon.py 生成对冲标注+台账；"信用卡月账单汇总验算"表核对 应还=周期明细合计
5. **同步+出盘**：全量回写明细表（先 clear_range_cells！）→ gen_dashboard.py → open 仪表盘
6. **净额对齐**：仪表盘总额必须与表格 SUMIFS 逐分一致；不一致先查符号/口径再交付

## 铁律（历次返工换来的，违反必错）

1. 明细表禁止任何"汇总行"——要真逐笔（零钱月度汇总、账单聚合行都已被用户点名废除）
2. 对冲禁止加行——S/T 列标注（对冲组+类型·入账/出账），退款负行 _hide 进对账台账
3. 写表格前必须 clear_range_cells（set_range_value_by_csv 不覆盖旧行，残留=重复计算）
4. 账户名列不能包含其他列关键词（"4738(逢,7623附属)"曾污染 SUMIFS 多算22,458）
5. 符号约定：支出为正；7623账单eml正数=消费负数=冲正（与其他源相反，必查）
6. 同日同额同商户同备注 = 重复，删1留1并备注"疑似重复已去重"

## 数据文件（工作区 账单存档/YYYY-MM/）

- `_v10_base.json` 三分类后基础行｜`_v10_rows.json` 最终行（对冲+隐藏标记）
- `_v10_recon.json` 对账台账｜`_dedup_audit.json` 源头跳过审计（17规则）

## 已定案口径（勿再问用户）

- 统计期 2026-03-01 起；当前净开销 XXX （历次修正：+房贷77,000 −婚礼报销N −重复569.96 −账单拆分差等）
- 房贷=8316→工行MORTGAGE_ACCT_NO 月供12,000（3月/6月流水无记录，或为7/1补缴5,000模式）
- 食品代买：父亲6,000/岳父岳父5,000/阿姨D阿姨500/梁阿姨300

- 三分类法：GB统计局八大类+扩展 / QS记账软件风格 / ZFB支付宝风格，每笔同挂三套
