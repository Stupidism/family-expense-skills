# 去重与对账

原则（用户铁律）：**对冲绝不加行**——全部用明细表 S/T 列标注；退款负行 `_hide` 进对账台账（主明细隐藏、净额照计）。

## 三类去重

### 1. 源头跳过（渠道 vs 银行/账单双记）
- 支付宝8551/6893/1479 渠道全跳（对应银行流水/账单已含）
- 信用卡账单周期窗口内渠道侧跳过（窗口表见 bill-source-parsing）
- 全部跳过规则登记 `_dedup_audit.json`（R01-R17，含每笔被跳明细，可审计）

### 2. 配对冲销（退款↔原消费）
- 匹配：金额相等 + counter相同/包含，或同渠道±2元且日期临近
- 配成对：原行标 offsetGroup=Gxxx+reconRole=debit；退款负行标 credit+_hide
- 未配负数行（拼多多小额等）留在审计台"未配对"区

### 3. 同日同额重复
- 判定：同日+同金额+同商户+同备注 完全一致 → 删1留1，保留行备注"疑似重复已去重(原N笔同刻)"
- 注意排除真两笔：两辆车（粤BBF3808/粤BJ95108）、逢暖各一笔同额同商户——查 note/时间戳/车牌差异再删

## 对账台账（_v10_recon.json，165组）

| 类型 | 组数 | 结构 |
|---|---|---|
| 退款冲销 | 18 | 左出账⇄右退款入账 |
| 转账退回 | 1 | 搭伙同事2000×2⇄退回×2 |
| 信用卡还款 | 19 | 储蓄卡-X⇄信用卡+X（双向不计开销，从R12恢复） |
| 渠道/银行双记 | 127 | 渠道侧采用(分类准)⇄银行侧免记 |

每组：gid/type/left[]/right[]/note；组头✓平衡或△差额。

## 识别规则（过卡/还款/内部）

- **过卡资金**：大额进出对冲（如8/17支付宝特约+N ↔ 8/25三笔-N）→ 不计消费，配对组
- **信用卡还款**：银行流水"信用卡自动还款/二代支付"→ 对账组，不进开销
- **家庭内部**：逢⇄暖互转、转父母（代存类）→ 排除类，不计净开销
- **公积金/理财申赎/结息**：非消费排除（R12/R13审计清单）
- **部分退款**：净额行+partialRefund标记+"含部分退款(净额)"

## 账务闭环验证

任何拆分/去重后必验：
```
净额 = Σ(非排除行amt)   （KPI口径，含隐藏负行）
展示层合计 = 净额 − Σ(隐藏负行)  （对冲净0）
账单净额 = 应还 − 上期结转（验算表勾稽）
```
示例：7623九月账单 16,214.14(正) − 3,377.46(冲正) − 173(防重) = 12,836.68 = 账单净13,009.68−173 ✓
